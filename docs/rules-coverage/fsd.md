# Rules coverage: Full Spectrum Dominance (`fsd-1.7`)

- **Source:** Full Spectrum Dominance Digital Living Rulebook v1.7.1 (Pantalone & Valsecchi, free PDF), core
  chapters: Core Concepts, The Game Round, Combat, Building Your Force, Behemoths, Terrain, Special Rules, and the
  generic part of Scenarios (Objectives and Victory Points, Controlling and Contesting, Victory Cards, Losing VPs,
  End-game). The lore chapters, faction gameplay sections and the individual scenarios were not audited.
- **Audited:** 2026-10-08 (issue #55).
- **Code:** `fsd` = `src/core/content/examples/fsd.ts`; `checks` = `src/systems/fsd/checks.ts`. Core engine pieces
  are named by file under `src/core/`.
- **Tests:** **F** = `src/systems/fsd/fsd.test.ts` (describe "Full Spectrum Dominance in play"), **A** =
  `src/systems/fsd/audit.test.ts` (describes "FSD rules audit: …").
- Rule names and our own short paraphrase only; no rules text, card stats or points.

Status key: **automated** (the app does it), **advisory check** (the app warns, the player decides),
**manual reminder** (the app shows it at the right time, the player resolves it), **missing** (nothing).

## Summary

Counts (rows above): **automated 84**, **advisory check 10**, **manual reminder 22**, **missing 11**.

Engine gaps (#57), from **automated 80**, **advisory check 5**, **manual reminder 5**, **missing 37**: the AD Pool
and Capacity follow the game size; multiple attacks (x2, x3) at a target each in one action; arcs of fire; terrain
movement by unit type and terrain areas, checked along each base's path (core `TerrainCategoryDef.movement`); unit
special rules shown for the unit activated, moving or reacting (core `AbilityTiming.on`); phase and action reminders
(core `Segment.hint`, unit action hints now shown under the unit's actions); attack-panel reminders for transported
units, wrecks, behemoth System damage and lost when firing; table warnings for overlapping bases, an army over the
game size and a Unique unit fielded twice.

Fixed in this audit (each with a test in A):

- ARM damage dropped the save die two sizes (the status's relative effect was applied to the model and again to
  the unit); now one size, applied in the save step.
- Per Base attacked from every base; now only bases in range (up to double) and in sight of the target.
- Close combat at exactly 1 DU let weapons with a 1 DU minimum range attack.
- Getting pinned didn't end interacting.
- A behemoth that reacted with a System couldn't activate its Core later, and a System couldn't react after the
  Core activated.
- Unsaved hits on a multi-base unit could go on unseen bases while seen ones remained (unseen now go last).

Added: Short Range, Contact, Indirect Fire (+1), Heavy (after moving); reminders for the other weapon and unit
special rules; a coherence warning after a base is lost.

**Known wrong:** none left in the system's own files.

Since fixed in the core (#55): initiative each round with the best unpinned Command; status changes no longer
applied twice; only enemy bases block sight, tall ones only by tall ones; blocking terrain gives cover only when
it hides part of the target; hits beyond the seen bases are lost.

**Needs core change:**

- Selective Fire (ignore enemy bases for sight) needs a sight query that leaves enemy bases out; it stays a
  reminder. (Since #57 the weapon is in the target filter's scope: Indirect Fire and arcs of fire use it.)
- Reactions that answer a reaction (chains): one reaction per action is offered.

Dogfood #54 (folded into #55): the log names the units a command activation brings along (fsd.test.ts > "commands nearby units and ends the round when both players pass"); an attack with no hits ends without save or damage rolls (core/content/runner.test.ts > "goes straight to the end when nothing hits: no wound, save or damage rolls (dogfood #54)").
