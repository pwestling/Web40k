- **At a real table** (the phone companion) nothing is measured. Those are player-confirmed by design and aren't counted as separate rows.

## Summary

- **automated:** 31
- **advisory check:** 3 (Move distance, and the two wreck-movement rows, which are the same rule listed twice)
- **manual reminder:** 0
- **missing:** 0

**Known wrong:** none left. Four were fixed here:

1. A unit could act again after its activation, during another unit's activation, or on the other side's go.
2. Shooting checked sight and range for the whole unit rather than for one shooter.
3. Holding a lantern was measured from the model's centre.
4. A thicket seen past gave no cover under true line of sight.

**Needs core change:**

Since fixed in the core (#55): `roundEnd` scoring takes `fromRound`, so The Last Lantern isn't asked in round 1.
Since fixed in the core (#57): a move whose path crosses a `blocksMovement` category (a wreck) is flagged in Table
warnings (core/content/moves.ts); the module's end-of-move wreck check went, and the version went to 1.3.2
(`RULES.md`, `rulebook.json` and the gallery row's version and fingerprint updated).

- **Plain activations, `startActivation` (core turn.ts).** It doesn't refuse a unit that already has `status.activated` this round. **`script/start` (core actions.ts)** doesn't recheck the action's `available`. The module now refuses both through `available`, which the UI and bots use, but a raw intent can still bypass it in any package game.
