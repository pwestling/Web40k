# Rules coverage: Warhammer 40,000 (system `forty-k-11`)

- **Source:** the auditor's own knowledge of the 40k core rules (10th edition structure), checked against the
  11th-edition changes the repo already encodes (core stratagems from commit a90dfe5, the terrain categories
  and the 2"/5" engagement and 2"/9" coherency values in `src/systems/wh40k/rules.ts`). Sections walked: Core
  Concepts, Command phase, Movement phase, Shooting phase, attack sequence, Charge phase, Fight phase, weapon
  abilities, core abilities, core stratagems, objective control, terrain and line of sight, transports,
  aircraft, reserves, mission scoring.
- **Date:** 2026-10-08.
- **IP:** this file lists rule names and our own one-line notes about what the code does. It quotes no rules text.
- **Edition caveat:** where 10th and 11th edition may differ (engagement range, coherency, terrain, Hazardous,
  stratagem costs), the repo's 11th-edition values are kept as they are and marked "edition value, unverified".
  None of them is counted as wrong.

Status key: **automated** (the app does it), **advisory check** (the app warns, the player decides),
**manual reminder** (the app shows it at the right time, the player resolves it), **missing** (nothing).

Paths are relative to `src/`. Main files: `core/content/examples/forty-k.ts` (the data, written `fk` below),
`systems/wh40k/rules.ts`, `checks.ts`, `module.ts`, `missions.ts`. "audit" means `systems/wh40k/audit.test.ts`.

## Summary

Counts (rows above, some rules appear in two sections): **automated 73**, **advisory check 12**, **manual reminder 23**, **missing 2**.

### Fixed in this audit

1. "Engaged" was never derived (the data asked for a status nothing set). Fall Back was never offered. Normal
   move, Advance and charges were allowed while engaged. Only units that charged could fight. A new module
   function `engaged` (module.ts) now answers it from the table. Tests: audit > offers Fall Back only when
   engaged, and Normal move and Advance only when not; audit > a unit engaged with the enemy may fight, even in
   the opponent's turn and without charging.
2. Heavy always gave +1 to hit because nothing set `moved`. The move actions now set it, `marksMoved` catches
   moves made by hand, and `stationary` is cleared each turn. Test: audit > Heavy: +1 to hit only if the unit
   didn't move this turn.
3. Battle-shock lasted all battle (`duration: "battle"`, and durations aren't applied). It now clears when the
   unit's turn begins. Test: audit > lasts until the start of the unit's next turn, and Insane Bravery lifts it.
4. Insane Bravery cost CP and did nothing. It now lifts Battle-shock. Same test.
5. A unit could take Remain stationary and then Advance, and so on. Now it gets one move per turn. Test: audit >
   makes one move a turn: Remain stationary, Normal move or Advance.
6. Added: engaged units shoot only Pistols unless they are a Monster or Vehicle; a warning when reserves arrive in
   round 1; reminders for Infiltrators, Firing Deck and Deadly Demise by name.

### Known wrong

- None open. Partial automations with a core cause are listed below.

### Needs core change

Since fixed (#55): Melta per bearer (automated when all are in half range, else a reminder); units arriving
from reserves count as moved; stratagem "unengaged" filters use the module's `engaged` function (derived statuses
are no longer needed for them).

Since fixed (#57): conditional reminders (a reminder, ability timing or core rule reminder shows only while its `if`
holds); `actionTargets` takes the chosen weapon (Indirect Fire) and a target `notWhen` gives the reason a target
shouldn't be picked; the engine fires "action.resolved" when a procedure or an attack-panel attack ends (Hazardous);
an advisory fight order (fight.ts). Charge targets are listed as within 12" or not (the charge declaration UI is
UX 396's).

- **Charge must end engaged with every target:** needs the declared targets on the charge (UX 396).
- **Sticky objectives:** detachment and mission rules; players track them.

Dogfood #54 (folded into #55): cover worsens Ballistic Skill rather than modifying the hit roll; a "your Command phase" rule is listed only in its owner's Command phase (audit > "lists a 'your Command phase' rule only in its owner's Command phase (dogfood #54)"); an attack with no hits ends without wound, save or damage rolls (core/content/runner.test.ts > "goes straight to the end when nothing hits: no wound, save or damage rolls (dogfood #54)").
