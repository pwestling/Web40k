# Writing Brinewatch

Brinewatch was written to prove the SDK on a second, different game (#69): model-by-model goes with action points, reactions, height, hidden deployment and a campaign. Every place the SDK or the engine couldn't do what the game needed was fixed there, generically, rather than worked around in the package. Each is documented in [docs/packages.md](../../docs/packages.md).

## The engine and the SDK

| Got in the way                                                                                                                                                | Fixed                                                                                                                                                                                                                                                                                                                                       |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A go in a game of plain activations was one move and one action. A game of action points (two a go, spent on moves and actions in any order) couldn't say so. | A slot's `actionsPerActivation` is each go's action points in plain activations (a number or a `const.` ref). `CodeAction.cost` says what an action spends (1 by default, 0 for a free one). A go lasts while points are left and ends when they're spent (core turn.ts `actionPointsLeft`, `spendActionPoints`; reducer.ts `script/step`). |
| Nothing stopped an action the unit couldn't pay for.                                                                                                          | The host refuses it and the card greys it out with "Not enough action points left" (core script.ts `pointsShort`, used by the sandbox's card rows and the computer players).                                                                                                                                                                |
| A package couldn't react to a move: what a move costs, or a guard who sees it.                                                                                | The `moved` turn hook, after each move of a unit in the battle (core script.ts `hookIntents`; `TurnHooks.moved`).                                                                                                                                                                                                                           |
| A go stayed open when its model was taken out in the middle of it (shot by a guard as it moved), so the game waited on a dead model.                          | A go ends when its acting unit has no models left (core reducer.ts).                                                                                                                                                                                                                                                                        |
| The computer players never took a reserve unit's code actions, so a hidden Lurker never emerged.                                                              | In plain activations, units in reserve offer their code actions (src/bot/player.ts, src/soak/bot.ts); they still don't move.                                                                                                                                                                                                                |
| The computer players never climbed: their moves kept models on the ground, and stepping off a floor left them in the air.                                     | `BotTuning.climbs` has them try moves up onto the nearest floors and block tops (src/soak/bot.ts `perches`); every move settles a model on what it stands on (core `settleZ`). The soak bot climbs in every game.                                                                                                                           |
| A game's `BotTuning.evaluate` saw only the state, so it couldn't ask about sight or cover.                                                                    | It gets a GameView too (src/bot/evaluate.ts).                                                                                                                                                                                                                                                                                               |
| The soak bot always acted before moving in a go, so it never moved and then shot.                                                                             | In games of action points it moves first some of the time (src/soak/bot.ts).                                                                                                                                                                                                                                                                |
| The rules page and print and play said warbands, units and lanterns, and showed a model's name only once per unit.                                            | `Rulebook.words` (the game's own words, and the marker reach for the gauge) and `Rulebook.terrainColors`; a unit's role and its models' abilities are shown when a game has named models (src/printplay). Rift Lanterns' pages are unchanged.                                                                                               |
| The review benchmark could only bench built-in games.                                                                                                         | `scene`'s `systemPkg` loads a package game for the benchmark (src/review/bench/build.ts).                                                                                                                                                                                                                                                   |
| The app's Play now, Play the computer, At a real table and event play knew only Rift Lanterns.                                                                | They take any of the app's own games (src/games/riftLanterns.ts `ownGame`, `playOwnGame`, `playOwnAtTable`, `installOwnGame`).                                                                                                                                                                                                              |

## What's left

- The review trusts Brinewatch's move decisions only: its shots and fights ranked right 26 of 30 times over six seeds (87%), short of the 90% bar. A shot here is two or three dice, so the review's dice decide more than in the other games.
- Sharp thinks for 20 to 40 seconds over a whole game, up to about 8 seconds for one go: line of sight to every enemy, for every move it tries. It caches sight by position, but a game with many tall ruins could be slow on a phone.
