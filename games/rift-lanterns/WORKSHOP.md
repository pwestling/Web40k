# Writing Rift Lanterns in the workshop

Rift Lanterns was written as the module workshop's proof (#42): one file, loaded into the workshop, played on its test table and soaked by its bot after each change. This is every place the workshop or the SDK got in the way, and what was done about it in the same pass. (The file was typed in an editor outside the browser and pasted into a workshop draft; everything after that, the saving, test table and soak runs, went through the workshop.)

## The SDK

| Got in the way                                                                                                                                                                                                                               | Fixed                                                                                                                                                                                                                                                                                         |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A package game couldn't have missions. `SystemModule.missions` existed for built-in games, but missions are code (`setup`, `suggest`) and nothing carried them out of the sandbox, so a package game had no objectives and nothing to score. | `PackageApp.missions`. The sandbox works out each mission's setup for the default table (the app scales it to the table played on) and answers every `suggest` as the game goes, for each scoring moment and each card; the app reads those answers. Nothing about missions runs on the page. |
| Only two armies. `sample(seat)` gives one army per side, so a game with four factions couldn't offer them.                                                                                                                                   | `PackageApp.armies`: every sample army players pick from. **Add an army** shows a list of them; **Play now** picks two at random.                                                                                                                                                             |
| No way to say what models look like. Every package model was the same grey pill.                                                                                                                                                             | `look` on a sample army's model: `{ shape, color }`, drawn as a procedural stand-in (trooper, brute, robed, beast, walker, drone, vehicle) in the given colour, on the player's coloured base. `height` sets its line-of-sight height.                                                        |
| Terrain had to be written as raw solids: walls, floors and blocks, by the inch.                                                                                                                                                              | A layout's terrain entry can name a terrain template: `{ template: "Ruin", id, position, facing }`. `templateCategory` says what each template counts as in the game.                                                                                                                         |
| A sample model's own `base` was ignored when deployed (the unit's was used).                                                                                                                                                                 | Models now keep their own base.                                                                                                                                                                                                                                                               |
| "What can I do now?" said "Nothing to do this phase" in package games: it only knew built-in actions.                                                                                                                                        | The sandbox reports which code actions each unit can take now, and the hint lists them. In an activation game it also says a unit can be dragged to move, or that nothing is in reach yet.                                                                                                    |
| A package can't import the app's helpers (deployment strips, who holds an objective), so the game carries its own copies.                                                                                                                    | Not changed: a package is one self-contained file on purpose. The helpers are short, and the game file shows them for others to copy.                                                                                                                                                         |

## The workshop

These overlap with UX review 51 (items 307-316), which was done in the same pass.

| Got in the way                                                                                     | Fixed                                                                                                                                                                                                                                                                                                                 |
| -------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A broken draft still said "Saved and reloaded", the rules quietly stopped, and errors had no line. | Each save is checked first: parsed for syntax errors (an unclosed bracket is named where it opens), then loaded in a sandbox as the table would load it. A broken draft isn't saved: the note says why and where, and the line is marked in the editor. Errors from the draft's own code carry their line and column. |
| Mistyped data (`rounds: "five"`, a `defaultDie` that isn't a die) passed silently.                 | A shape check of the system names the key and marks its line: "system.turn.rounds: should be a number (got "five")".                                                                                                                                                                                                  |
| Changing a sample army and saving changed nothing on the running table, without saying so.         | The note says the armies, missions or table changed and to restart the test table. Saving with nothing changed says so instead of logging another package change.                                                                                                                                                     |
| The army showcase played on every test table restart.                                              | Test tables start without it.                                                                                                                                                                                                                                                                                         |
| The soak bot said "to round 5" for a game that ended after 4.                                      | It says the game was played to the end, or where it stopped.                                                                                                                                                                                                                                                          |
| The SDK tab was the raw TypeScript file, and the templates pointed at repository paths.            | The SDK tab is a readable list of the commands, the game view and every key and snippet, with the full types folded below. Templates point at the SDK tab. New keys (`armies`, `missions`, `templateCategory`, `look`, terrain templates) have completions and snippets.                                              |
| The workshop couldn't start from a whole finished game.                                            | Rift Lanterns is a workshop template: a finished game to take apart.                                                                                                                                                                                                                                                  |
| Export didn't say how to host a file for the gallery.                                              | It says how (a gist's Raw link, or a repository's). Gallery rows open straight in the workshop.                                                                                                                                                                                                                       |
| On a phone the controls were small, and over a table the editor shrank to a few lines.             | 44px controls on touch screens; on a narrow screen the workshop takes the screen and **Table** switches to the table and back.                                                                                                                                                                                        |

## What's left

- The editor's completions are a table, not a type checker: a wrong key in a unit's stats or a misspelt event type is only found when it misbehaves on the table.
- Mission setup is worked out once for the default table and scaled, so a mission that places things by table size in a non-proportional way will be off on other table sizes.
- The stand-in shapes are simple primitives. Uploaded figures still replace them per unit, as in any game.
